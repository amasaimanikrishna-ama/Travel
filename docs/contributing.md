# Contributing to TravelEase

Thank you for your interest in contributing to the TravelEase platform!

## Code of Conduct
Please be respectful and constructive in all community and team interactions.

## Branching Strategy
- `main`: Production-ready release code.
- `develop`: Integration branch for new features.
- `feature/<feature-name>`: New feature branches.
- `fix/<issue-name>`: Bug fixes.

## Development Workflow
1. Fork and clone the repository.
2. Create a new feature branch (`git checkout -b feature/awesome-feature`).
3. Follow the project's code conventions and run linters/tests.
4. Commit your changes with clear semantic messages (`feat:`, `fix:`, `docs:`).
5. Push to your branch and submit a Pull Request.

## Pull Request Guidelines
- Include a descriptive title and summary of changes.
- Ensure all automated unit and integration tests pass.
- Update documentation in `docs/` if you introduce API or architecture changes.
